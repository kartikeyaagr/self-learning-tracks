question: "Your CNN gets 99% on MNIST but 60% on the same digits shifted 6 pixels. Convolution is translation-equivariant, so why does this happen?"
answer: "Equivariance holds for convolution layers, but pooling with stride, the final flatten and the dense layer tie features to positions. A 6-pixel shift moves features to other dense-layer inputs never seen at those positions in training. Global average pooling and shift augmentation make the model far more tolerant."

html: "<section class=\"art\"><h2>Convolutional neural networks: looking for small patterns everywhere</h2><p class=\"cite\"><span class=\"lab\">Based on</span> Hvass-Labs TensorFlow Tutorial 02 · Stanford CS231n notes, &quot;Convolutional Neural Networks&quot; · Fanout 04.02</p><h3>Why this matters</h3>\n<p>The linear model from 04.01 compares the whole image with one template, so a digit shifted by two pixels confuses it. Convolutional networks (CNNs) fix this by looking for <strong>small local patterns</strong> (edges, corners, curves) and looking for them <strong>everywhere</strong> in the image. They take MNIST from 92% to about 99%, and the same idea runs inside almost every vision model.</p>\n<h3>The idea in plain words</h3>\n<ul>\n<li>A <strong>kernel</strong> (or filter) is a tiny grid of weights, for example 3×3.</li>\n<li><strong>Slide</strong> it over the image. At each position, multiply the 9 pixels under it by the 9 weights and add them up. That sum is one output pixel.</li>\n<li>The grid of all those sums is a <strong>feature map</strong>. It is bright where the image contains the kernel&#39;s pattern.</li>\n<li>A layer has many kernels (say 16), so it produces 16 feature maps. The next layer&#39;s kernels look at all 16 maps at once and find patterns made of patterns.</li>\n<li><strong>Pooling</strong> (for example 2×2 max pooling) shrinks a map by keeping only the largest value in each 2×2 block. It makes the network less sensitive to exact positions.</li>\n</ul>\n<p>Two properties make CNNs work:</p>\n<ul>\n<li><strong>Weight sharing.</strong> The same 9 weights are used at every position, so a 3×3 layer has 9 weights per input–output channel pair, not millions.</li>\n<li><strong>Locality.</strong> Each output depends only on a small patch, which matches how images are built.</li>\n</ul>\n<h3>Worked example 1: one output pixel by hand</h3>\n<p>Image patch and the vertical-edge (Sobel) kernel:</p>\n<div class=\"math-block\"><span class=\"katex-display\"><span
