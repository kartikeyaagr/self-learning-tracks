Training runs crash at hour 9. The best model is often from an earlier epoch than the last one. Saving correctly is the difference between losing a day and losing a minute, and it is how you pick the model that actually generalises best.</p>\n<h3>The idea in plain words</h3>\n<p>A <strong>checkpoint</strong> is a snapshot of everything needed to continue training:</p>\n<ul>\n<li>the model&#39;s weights,</li>\n<li>the optimiser&#39;s state (Adam&#39;s two running averages for every weight),</li>\n<li>the step number, and ideally the random seed and data position.</li>\n</ul>\n<p>Saving only the weights is enough to <em>use</em> the model; it is not enough to <em>continue training</em> it exactly.</p>\n<p><strong>Early stopping</strong> uses checkpoints: after each epoch, measure validation accuracy; if it is the best so far, save. When it stops improving for a few epochs (the &quot;patience&quot;), stop and reload the best one.</p>\n<h3>Worked example: early stopping on real numbers</h3>\n<p>Validation accuracy after each epoch, patience 2:</p>\n<div class=\"tbl\"><table>\n<thead>\n<tr>\n<th>Epoch</th>\n<th>1</th>\n<th>2</th>\n<th>3</th>\n<th>4</th>\n<th>5</th>\n<th>6</th>\n</tr>\n</thead>\n<tbody><tr>\n<td>Val. accuracy</td>\n<td>0.952</td>\n<td>0.968</td>\n<td>0.974</td>\n<td>0.973</td>\n<td>0.971</td>\n<td>—</td>\n</tr>\n<tr>\n<td>Best so far?</td>\n<td>save</td>\n<td>save</td>\n<td>save</td>\n<td>no (1)</td>\n<td>no (2) → stop</td>\n<td></td>\n</tr>\n</tbody></table></div>\n<p>Training stops after epoch 5 and restores epoch 3&#39;s weights (0.974). Without checkpoints you would keep epoch 5 (0.971) and lose the best model.</p>\n<figure class=\"dg viz\" data-viz=\"overfit\" data-p=\"{}\"><div class=\"vz\"></div><figcaption>Why early stopping works: training error keeps falling while validation error eventually rises. Saving the best validation checkpoint picks the bottom of the teal curve.</figcaption></figure>\n<h3>Worked example 2: how big is a checkpoint?</h3>\n<p>The 04.02 CNN has 242 K float32 weights: about 1 MB. With Adam&#39;s two moments the full checkpoint is 3 times as much, about 3 MB. For a 7 B-parameter model the same rule gives 28 GB of weights (float32) and 84 GB for a full checkpoint. Storage and saving time matter at scale.</p>\n<h3>In code</h3>\n<pre class=\"code\"><code class=\"language-python\">ckpt = tf.keras.callbacks.ModelCheckpoint(&quot;best.keras&quot;, monitor=&quot;val_accuracy&quot;, save_best_only=True)\nstop = tf.keras.callbacks.EarlyStopping(monitor=&quot;val_accuracy&quot;, patience=2, restore_best_weights=True)\nmodel.fit(xtr, ytr, validation_split=0.1, epochs=50, callbacks=[ckpt, stop])\n\nmodel = tf.keras.models.load_model(&quot;best.keras&quot;)       # architecture + weights + optimiser state\n</code></pre>\n<p>To resume exactly in a custom loop, use <code>tf.train.Checkpoint(model=model, optimizer=opt, step=step)</code> with a <code>CheckpointManager</code>, the TF equivalent of saving <code>model.state_dict()</code> and <code>optimizer.state_dict()</code> in PyTorch.</p>\n<h3>Common mistakes</h3>\n<ul>\n<li><strong>Choosing the checkpoint on the test set.</strong> That leaks test information into your choice. Use a validation set; touch the test set once at the end.</li>\n<li><strong>Saving to the Colab disk.</strong> It vanishes when the runtime resets. Save to Google Drive.</li>\n<li><strong>Not saving the optimiser.</strong> Restarting Adam from zero causes a loss spike and is not the same run.</li>\n</ul>\n<h3>Try it yourself</h3>\n<ol>\n<li>Validation accuracies 0.90, 0.92, 0.91, 0.93, 0.92, 0.92 with patience 2.
