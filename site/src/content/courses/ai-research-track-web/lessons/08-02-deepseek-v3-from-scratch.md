Two architectural ideas made it efficient: a <strong>mixture of experts</strong> that uses only 37 B of its 671 B parameters per token, and <strong>multi-head latent attention</strong> that shrinks the KV cache dramatically. Both now appear in many new models.</p>\n<h3>Mixture of experts in plain words</h3>\n<p>Replace each MLP with many smaller MLPs, the <strong>experts</strong>, and a small <strong>router</strong> that picks a few of them for each token.</p>\n<ul>\n<li>The model <em>stores</em> the knowledge of all the experts (large total size).</li>\n<li>Each token <em>uses</em> only a few (small compute per token).</li>\n</ul>\n<p>The router is a linear layer giving one score per expert; the token goes to the top-<span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.6944em;\"></span><span class=\"mord mathnormal\" style=\"margin-right:0.0315em;\">k</span></span></span></span> scorers, and their outputs are added up, weighted by the (normalised) scores.</p>\n<h3>Worked example 1: DeepSeek-V3&#39;s numbers</h3>\n<ul>\n<li>61 layers; the first 3 use a normal MLP, the rest use MoE.</li>\n<li>Each MoE layer: <strong>1 shared expert</strong> (every token uses it) plus <strong>256 routed experts</strong>, of which each token uses <strong>8</strong>.</li>\n<li>Total parameters 671 B; active per token 37 B, about 5.5%.</li>\n<li>Trained on 14.8 trillion tokens.</li>\n</ul>\n<p>The shared expert learns what every token needs; the routed experts can specialise.</p>\n<h3>Worked example 2: the load-balancing problem</h3>\n<p>If the router learns to like a few experts, they get overloaded (on real hardware, tokens get dropped or GPUs wait) and the rest never learn. Earlier models added an <strong>auxiliary loss</strong> that penalised uneven load, but that loss also fights the main objective.</p>\n<p>DeepSeek-V3&#39;s fix, <strong>auxiliary-loss-free balancing:</strong> keep a bias <span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.8444em;vertical-align:-0.15em;\"></span><span class=\"mord\"><span class=\"mord mathnormal\">b</span><span class=\"msupsub\"><span class=\"vlist-t vlist-t2\"><span class=\"vlist-r\"><span class=\"vlist\" style=\"height:0.1514em;\"><span style=\"top:-2.55em;margin-left:0em;margin-right:0.05em;\"><span class=\"pstrut\" style=\"height:2.7em;\"></span><span class=\"katex-sizing reset-size6 size3 mtight\"><span class=\"mord mathnormal mtight\">e</span></span></span></span><span class=\"vlist-s\">​</span></span><span class=\"vlist-r\"><span class=\"vlist\" style=\"height:0.15em;\"><span></span></span></span></span></span></span></span></span></span> for each expert, used <strong>only for choosing</strong> the top-<span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.6944em;\"></span><span class=\"mord mathnormal\" style=\"margin-right:0.0315em;\">k</span></span></span></span>, not for weighting outputs. After each step, lower <span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.8444em;vertical-align:-0.15em;\"></span><span class=\"mord\"><span class=\"mord mathnormal\">b</span><span class=\"msupsub\"><span class=\"vlist-t vlist-t2\"><span class=\"vlist-r\"><span class=\"vlist\" style=\"height:0.1514em;\"><span style=\"top:-2.55em;margin-left:0em;margin-right:0.05em;\"><span class=\"pstrut\" style=\"height:2.7em;\"></span><span class=\"katex-sizing reset-size6 size3 mtight\"><span class=\"mord mathnormal mtight\">e</span></span></span></span><span class=\"vlist-s\">​</span></span><span class=\"vlist-r\"><span class=\"vlist\" style=\"height:0.15em;\"><span></span></span></span></span></span></span></span></span></span> for overloaded experts and raise it for idle ones by a small fixed amount. The load evens out without touching the loss.</p>\n<figure class=\"dg viz\" data-viz=\"moe\" data-p=\"{}\"><div class=\"vz\"></div><figcaption>400 tokens routed to experts; the router prefers the first few. MLA goes further: it caches one <strong>compressed latent vector</strong> per token per layer, 512 numbers, and rebuilds each head&#39;s keys and values from it with learned matrices when needed. A small extra piece of 64 numbers carries the RoPE position information, since rotations cannot pass through the compression.</p>\n<p><strong>Numbers:</strong> <span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:1em;vertical-align:-0.25em;\"></span><span class=\"mopen\">(</span><span class=\"mord\">512</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span><span class=\"mbin\">+</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span></span><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:1em;vertical-align:-0.25em;\"></span><span class=\"mord\">64</span><span class=\"mclose\">)</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span><span class=\"mbin\">×</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span></span><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.8889em;vertical-align:-0.1944em;\"></span><span class=\"mord\">61</span><span class=\"mord text\"><span class=\"mord\"> layers</span></span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span><span class=\"mbin\">×</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span></span><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.8889em;vertical-align:-0.1944em;\"></span><span class=\"mord\">2</span><span class=\"mord text\"><span class=\"mord\"> bytes</span></span><span class=\"mspace\" style=\"margin-right:0.2778em;\"></span><span class=\"mrel\">≈</span><span class=\"mspace\" style=\"margin-right:0.2778em;\"></span></span><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.6444em;\"></span><span class=\"mord\">69</span></span></span></span> KiB per token. It gives a denser training signal, and at inference it can be used for speculative decoding (guess two tokens, check them in one pass).</p>\n<h3>Worked example 3: compute for one token</h3>\n<p>Rule of thumb: a forward pass costs about <span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.7278em;vertical-align:-0.0833em;\"></span><span class=\"mord\">2</span><span class=\"mord\">×</span></span></span></span> (active parameters) FLOPs per token.
