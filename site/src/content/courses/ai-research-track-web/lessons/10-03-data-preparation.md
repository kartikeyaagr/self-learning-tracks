Most failed fine-tunes are data problems: the wrong format, the loss computed on the wrong tokens, answers cut off by truncation, or duplicates of the test set. Getting these right is unglamorous and decisive.</p>\n<h3>Chat templates in plain words</h3>\n<p>A chat model never sees &quot;user&quot; and &quot;assistant&quot; as labels. It sees one long token sequence, with <strong>special tokens</strong> marking where each turn starts and ends. Each model family has its own template. ChatML (used by Qwen and others) looks like:</p>\n<pre class=\"code\"><code>&lt;|im_start|&gt;user\nWhat is 12 times 7?&lt;|im_end|&gt;\n&lt;|im_start|&gt;assistant\n12 times 7 is 84.&lt;|im_end|&gt;\n</code></pre>\n<p>Fine-tuning data must use <strong>exactly</strong> the template the model will see at inference. Always build it with the tokenizer&#39;s own <code>apply_chat_template</code>.</p>\n<h3>Loss masking</h3>\n<p>You want the model to learn to write the <strong>assistant&#39;s</strong> replies, not to predict the user&#39;s questions. So the loss is computed only on assistant tokens: every other position gets the label <code>-100</code>, which PyTorch&#39;s cross-entropy ignores.</p>\n<p>Include the assistant&#39;s <strong>end-of-turn token</strong> in the loss. Otherwise the model never learns when to stop, and rambles at inference.</p>\n<figure class=\"dg viz\" data-viz=\"chatmask\" data-p=\"{}\"><div class=\"vz\"></div><figcaption>A two-turn conversation as tokens. Highlighted tokens count in the loss. Switch templates, toggle masking, and lower the maximum length to see truncation cut into an answer.</figcaption></figure>\n<h3>Worked example 1: what fraction is trained?</h3>\n<p>A typical example: a 300-token system prompt and question, then a 100-token answer. With masking, only 100 of 400 tokens (25%) carry loss. That is normal. The prompt still matters: the model reads it to produce the answer.</p>\n<h3>Worked example 2: truncation</h3>\n<p>Your maximum length is 2,048 tokens and 8% of your examples are longer. If you cut from the end, those examples lose (part of) their answers, and the model learns to stop mid-sentence. Better options: drop over-long examples, raise the limit, or cut from the middle of the context rather than the answer.</p>\n<h3>Worked example 3: cleaning</h3>\n<p>A checklist before training:</p>\n<ul>\n<li><strong>Exact and near duplicates:</strong> remove them (hashing, or MinHash for near-duplicates). Duplicates get over-weighted.</li>\n<li><strong>Decontamination:</strong> remove any example that overlaps your evaluation set, for example sharing a 13-token span with a test question. Otherwise your evaluation is meaningless.</li>\n<li><strong>Quality filter:</strong> read 50 random examples yourself. If 5 are bad, about 10% of the dataset is bad.</li>\n<li><strong>Balance:</strong> if 80% of examples are one type, the model will over-produce that type.</li>\n</ul>\n<h3>In code</h3>\n<pre class=\"code\"><code class=\"language-python\">msgs = [{&quot;role&quot;: &quot;user&quot;, &quot;content&quot;: &quot;What is 12 times 7?&quot;},\n        {&quot;role&quot;: &quot;assistant&quot;, &quot;content&quot;: &quot;12 times 7 is 84.&quot;}]\ntext = tok.apply_chat_template(msgs, tokenize=False)\nids = tok(text, return_tensors=&quot;pt&quot;).input_ids[0]\n\n# mask everything except the assistant reply\nprompt_len = len(tok.apply_chat_template(msgs[:1], add_generation_prompt=True))\nlabels = ids.clone(); labels[:prompt_len] = -100\n</code></pre>\n<h3>Common mistakes</h3>\n<ul>\n<li><strong>Hand-writing the template</strong> and getting a space or newline wrong. The model sees a format it was never trained on.</li>\n<li><strong>Forgetting the end-of-turn token in the loss.</strong></li>\n<li><strong>Training on test data by accident.</strong> Decontaminate before you look at any results.</li>\n<li><strong>Mixing templates</strong> from different model families in one dataset.</li>\n</ul>\n<h3>Try it yourself</h3>\n<ol>\n<li>An example has a 500-token prompt and a 50-token answer.
