question: "A teammate&#39;s training component mutates its config object to change the output path, and a later stage writes into the wrong folder. Which Python feature prevents this?"
answer: "Frozen dataclasses (<code>@dataclass(frozen=True)</code>): assignment to a field raises an error, so a stage cannot change shared settings. Return new values in an artifact object instead."

Training code written against <code>Model</code> works for a random forest, XGBoost or a network.</p>\n<h3>Logging instead of print</h3>\n<ul>\n<li><code>log.info(...)</code> goes to a file and the console with a timestamp and the module name; <code>print</code> goes nowhere useful on a server.</li>\n<li>Levels (<code>DEBUG</code>, <code>INFO</code>, <code>WARNING</code>, <code>ERROR</code>) let you turn detail up or down without editing code.</li>\n<li>Use <code>log.exception(...)</code> inside <code>except</code> to record the full traceback.</li>\n</ul>\n<h3>Common mistakes</h3>\n<ul>\n<li><strong>Hard-coded paths and numbers inside methods.</strong> Put them in the config.</li>\n<li><strong>Components that read global state.</strong> Pass everything in; then you can unit-test each one with a tiny CSV.</li>\n<li><strong>Catching every exception and continuing.</strong> A pipeline that silently writes an empty file is worse than one that crashes.</li>\n</ul>\n<h3>Try it yourself</h3>\n<ol>\n<li>Why make the config <code>frozen=True</code>?</li>\n<li>What should <code>DataIngestion.run()</code> return, and why not just write files?</li>\n</ol>\n<details><summary>Answers</summary><ol>\n<li>So no step can change a setting halfway through a run; the config you logged is the config that was used.</li>\n<li>An artifact object with the output paths.
