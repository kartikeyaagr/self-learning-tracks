Monitoring is how you find out before users tell you.</p>\n<p>The Google SRE book (ch. 6) reduces service monitoring to <strong>four golden signals</strong>: latency, traffic, errors and saturation. If you can only measure four things, measure those. It also insists on separating the latency of successful and failed requests: a fast stream of errors can make average latency look great. An ML service needs a fifth group the SRE book does not cover, about the <strong>model&#39;s behaviour</strong>: input statistics, prediction distribution, confidence, and, when labels arrive later, accuracy.</p>\n<p><strong>Prometheus</strong> is a time-series database that <strong>pulls</strong> metrics: every few seconds it scrapes an HTTP endpoint (conventionally <code>/metrics</code>) on each target and stores the values with timestamps and labels.</p>\n<h3>Metric types</h3>\n<div class=\"tbl\"><table>\n<thead>\n<tr>\n<th>Type</th>\n<th>What it is</th>\n<th>Example</th>\n</tr>\n</thead>\n<tbody><tr>\n<td>Counter</td>\n<td>Only goes up (resets on restart)</td>\n<td><code>http_requests_total{route=&quot;/predict&quot;,status=&quot;200&quot;}</code></td>\n</tr>\n<tr>\n<td>Gauge</td>\n<td>Goes up and down</td>\n<td><code>model_batch_queue_size</code>, GPU memory in use</td>\n</tr>\n<tr>\n<td>Histogram</td>\n<td>Counts of observations in cumulative buckets, plus sum and count</td>\n<td><code>request_latency_seconds_bucket{le=&quot;0.25&quot;}</code></td>\n</tr>\n<tr>\n<td>Summary</td>\n<td>Client-side quantiles</td>\n<td>Rarely used; cannot be aggregated across replicas</td>\n</tr>\n</tbody></table></div>\n<p>In Python, <code>prometheus_client</code> provides these. A FastAPI middleware that times every request and records it in a histogram labelled by route and status code gives you most of what you need. Exercise 1 builds exactly that middleware.</p>\n<p><strong>Label cardinality</strong> is the main way to break Prometheus: every distinct label combination is a separate time series. Never use user IDs, raw input text or request IDs as labels.</p>\n<h3>PromQL essentials</h3>\n<ul>\n<li><code>rate(http_requests_total[5m])</code>: per-second rate of a counter, averaged over 5 minutes. Always take <code>rate</code> of counters; raw counter values are meaningless across restarts.</li>\n<li><code>sum by (route) (rate(http_requests_total{status=~&quot;5..&quot;}[5m])) / sum by (route) (rate(http_requests_total[5m]))</code>: error ratio per route.</li>\n<li><code>histogram_quantile(0.95, sum by (le) (rate(request_latency_seconds_bucket[5m])))</code>: p95 latency across all replicas.</li>\n</ul>\n<h3>How histogram_quantile works</h3>\n<p>Histogram buckets are cumulative: <code>le=&quot;0.25&quot;</code> counts all observations at most 0.25 s.
