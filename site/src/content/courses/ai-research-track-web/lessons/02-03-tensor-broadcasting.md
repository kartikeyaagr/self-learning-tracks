question: "Your regression loss <code>((pred - y)**2).mean()</code> trains to a poor fit with no error. <code>pred</code> has shape (N,) and <code>y</code> has shape (N, 1). What happened?"
answer: "Broadcasting turned <code>pred - y</code> into an (N, N) matrix of every prediction minus every target, so the loss compares each prediction with all targets. Make shapes match (<code>y.squeeze(1)</code> or <code>pred[:, None]</code>) and assert <code>pred.shape == y.shape</code>; <code>F.mse_loss</code> warns about this case."

html: "<section class=\"art\"><h2>Tensor broadcasting: how shapes stretch to fit</h2><p class=\"cite\"><span class=\"lab\">Based on</span> NumPy broadcasting guide · PyTorch broadcasting semantics · d2l.ai §2.1.4 · Fanout 02.03</p><h3>Why this matters</h3>\n<p>Neural network code is mostly operations on arrays of different shapes: add a bias to a whole batch, subtract a mean from every row, scale every colour channel. Broadcasting lets you write these in one line with no loops. It is also the source of the most common silent bug in ML code. Learn the rule once and you will spot it.</p>\n<h3>The idea in plain words</h3>\n<p>When you combine two arrays with different shapes, PyTorch and NumPy try to <strong>stretch</strong> the smaller one to match, without copying any data.</p>\n<p><strong>The rule:</strong></p>\n<ol>\n<li>Write the two shapes one above the other, <strong>lined up on the right</strong>.</li>\n<li>If one shape is shorter, pad it on the <strong>left</strong> with 1s.</li>\n<li>Go axis by axis. Two sizes are compatible if they are <strong>equal</strong>, or <strong>one of them is 1</strong>.</li>\n<li>A size-1 axis is stretched to match. Otherwise it is an error.</li>\n</ol>\n<h3>Worked example 1: a bias for every row</h3>\n<p>A batch of 32 examples with 10 outputs has shape <code>(32, 10)</code>. The bias has shape <code>(10,)</code>.</p>\n<pre class=\"code\"><code>x     : (32, 10)\nbias  :     (10,)  -&gt; pad -&gt; (1, 10)\nresult: (32, 10)\n</code></pre>\n<p>Axis 1: 10 and 10 are equal. Axis 0: 32 and 1, so stretch the 1. Every row gets the same bias added. This is exactly what <code>nn.Linear</code> does.</p>\n<h3>Worked example 2: normalise each feature</h3>\n<p>Data <code>X</code> has shape <code>(100, 3)</code>: 100 people, 3 features (height, weight, age). You want each column to have mean 0.</p>\n<pre class=\"code\"><code class=\"language-python\">mu = X.mean(dim=0)        # shape (3,)\nX_centred = X - mu        # (100, 3) - (3,) -&gt; (100, 3)\n</code></pre>\n<p>Same pattern as above. Now centre each <strong>row</strong> instead:</p>\n<pre class=\"code\"><code class=\"language-python\">row_mu = X.mean(dim=1)    # shape (100,)\nX - row_mu                # (100, 3) - (100,)  -&gt; ERROR: 3 vs 100\nX - row_mu[:, None]       # (100, 3) - (100, 1) -&gt; works\nX.mean(dim=1, keepdim=True)   # gives (100, 1) directly\n</code></pre>\n<p><code>[:, None]</code> (or <code>.unsqueeze(1)</code>) adds an axis of size 1 so the shapes line up the way you meant.</p>\n<h3>Worked example 3: the silent bug</h3>\n<p>Predictions <code>pred</code> have shape <code>(N,)</code>. Targets <code>y</code> have shape <code>(N, 1)</code>, which is common when they come from a DataFrame column.</p>\n<pre class=\"code\"><code>pred: (N,)  -&gt; (1, N)\ny   : (N, 1)\npred - y  -&gt; (N, N)\n</code></pre>\n<p>Both axes broadcast, so there is <strong>no error</strong>. You get an <span class=\"katex\"><span class=\"katex-html\" aria-hidden=\"true\"><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.7667em;vertical-align:-0.0833em;\"></span><span class=\"mord mathnormal\" style=\"margin-right:0.109em;\">N</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span><span class=\"mbin\">×</span><span class=\"mspace\" style=\"margin-right:0.2222em;\"></span></span><span class=\"katex-base\"><span class=\"katex-strut\" style=\"height:0.6833em;\"></span><span class=\"mord mathnormal\" style=\"margin-right:0.109em;\">N</span></span></span></span> matrix holding every prediction minus every target. <code>((pred - y)**2).mean()</code> then trains your model to predict the average target for everything. The loss goes down a little, nothing crashes, and the model is useless.</p>\n<p><strong>Fix:</strong> make the shapes match (<code>y = y.squeeze(1)</code>) and add <code>assert pred.shape == y.shape</code> in your training code.</p>\n<figure class=\"dg viz\" data-viz=\"broadcast\" data-p=\"{}\"><div class=\"vz\"></div><figcaption>Pick a pair of shapes. A holds tens and B holds ones, so you can read off which entries were combined in each result cell. Solid cells are real data; dashed cells are the stretched copies, which are not stored in memory. Try the last option to see the silent bug.</figcaption></figure>\n<h3>Images: three dimensions, same rule</h3>\n<p>An image batch has shape <code>(B, 3, H, W)</code>: batch, colour channels, height, width. To normalise each colour channel with its own mean:</p>\n<pre class=\"code\"><code class=\"language-python\">mean = torch.tensor([0.485, 0.456, 0.406]).view(1, 3, 1, 1)\nx = (x - mean) / std     # (B,3,H,W) with (1,3,1,1) -&gt; (B,3,H,W)\n</code></pre>\n<p>Lined up on the right: W vs 1, H vs 1, 3 vs 3, B vs 1. All compatible.</p>\n<h3>Common mistakes</h3>\n<ul>\n<li><strong>The <code>(N,)</code> versus <code>(N, 1)</code> bug above.</strong> The most common one. Assert shapes in your loss function.</li>\n<li><strong>Forgetting <code>keepdim=True</code></strong> after a reduction, so the axis disappears and the shapes no longer line up.</li>\n<li><strong>In-place operations on the smaller tensor.</strong> <code>small += big</code> fails, because the result would not fit in <code>small</code>.</li>\n<li><strong>Thinking broadcasting copies data.</strong> It does not; the stretched axis has stride 0. But the <em>result</em> is full size, so <code>(10000, 1) + (1, 10000)</code> gives a 100-million-entry tensor.</li>\n</ul>\n<h3>Try it yourself</h3>\n<p>What is the result shape, or is it an error?</p>\n<ol>\n<li><code>(5, 1, 4)</code> and <code>(3, 1)</code></li>\n<li><code>(8, 6)</code> and <code>(8,)</code></li>\n<li><code>(2, 3)</code> and <code>(2, 1)</code></li>\n</ol>\n<details><summary>Answers</summary><ol>\n<li>Pad to <code>(1, 3, 1)</code>. Use <code>(8, 1)</code> to subtract per row.</li>\n<li><code>(2, 3)</code>. PyTorch, NumPy and TensorFlow agree on almost everything at this level, which is why the three guides read alike. The one rule that causes most shape bugs is broadcasting.</p>\n<h3>Vocabulary</h3>\n<p>Goodfellow et al. §2.1 use the words scalar, vector, matrix and tensor for arrays with 0, 1, 2 and more axes. Frameworks call the number of axes the <strong>rank</strong> or <code>ndim</code> (not the same as matrix rank from Lesson 01.03), and the tuple of sizes the <strong>shape</strong>. Three other attributes matter as much as the shape:</p>\n<ul>\n<li><strong>dtype.</strong> <code>float32</code> is the default for parameters. <code>bfloat16</code> and <code>float16</code> are used for speed and memory. <code>int64</code> is the default for indices. Mixing dtypes either raises an error or silently promotes, depending on the framework and operation.</li>\n<li><strong>device.</strong> CPU or a specific GPU. An operation on tensors from two devices is an error in PyTorch; TensorFlow will often copy for you, which hides a slow transfer.</li>\n<li><strong>requires_grad / trainable.</strong> Whether the autodiff system (Lesson 03.04) tracks operations on it.</li>\n</ul>\n<p>d2l.ai §2.1 gives a useful habit: read every new piece of code by writing the shape next to each line. In deep learning the conventions are worth memorising: images are <code>(B, C, H, W)</code> in PyTorch and <code>(B, H, W, C)</code> in TensorFlow by default; sequences are <code>(B, T, C)</code> for batch, time and channels; attention scores are <code>(B, heads, T_query, T_key)</code>.</p>\n<h3>The broadcasting rule</h3>\n<p>When an element-wise operation combines two tensors of different shapes:</p>\n<ol>\n<li>Line the shapes up <strong>from the right</strong>.</li>\n<li>Two dimensions are compatible if they are equal, or if one of them is 1.</li>\n<li>A missing dimension on the left is treated as 1.</li>\n<li>The result takes the larger size in each position.
