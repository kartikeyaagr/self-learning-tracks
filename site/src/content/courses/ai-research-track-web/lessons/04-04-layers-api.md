The TF1 module <code>tf.layers</code> (Hvass tutorial 03-B) was TensorFlow&#39;s first built-in answer. It has since been folded into <code>tf.keras.layers</code>, which is what you use now.</p>\n<h3>A layer from scratch, in both frameworks</h3>\n<pre class=\"code\"><code class=\"language-python\">class Dense(tf.keras.layers.Layer):\n    def __init__(self, units):\n        super().__init__(); self.units = units\n    def build(self, input_shape):              # called once, on first use\n        self.w = self.add_weight(shape=(input_shape[-1], self.units), initializer=&quot;glorot_uniform&quot;)\n        self.b = self.add_weight(shape=(self.units,), initializer=&quot;zeros&quot;)\n    def call(self, x):\n        return x @ self.w + self.b\n</code></pre>\n<pre class=\"code\"><code class=\"language-python\">class Dense(nn.Module):\n    def __init__(self, d_in, units):\n        super().__init__()\n        self.w = nn.Parameter(torch.empty(d_in, units)); nn.init.xavier_uniform_(self.w)\n        self.b = nn.Parameter(torch.zeros(units))\n    def forward(self, x):\n        return x @ self.w + self.b\n</code></pre>\n<p>The main difference is <strong>lazy shape inference</strong>. Keras creates weights in <code>build</code> when it first sees an input, so you only give the output size. PyTorch asks for the input size up front (<code>nn.LazyLinear</code> exists, but is rarely used). Keras&#39;s way is convenient; PyTorch&#39;s way means a model&#39;s parameter count is known before any data flows.</p>\n<h3>What a layer must track</h3>\n<ul>\n<li><strong>Trainable weights</strong> (kernel, bias) and <strong>non-trainable state</strong> (BatchNorm&#39;s running mean and variance). Keras: <code>layer.trainable_weights</code> and <code>non_trainable_weights</code>. PyTorch: <code>parameters()</code> and <code>buffers()</code>.</li>\n<li><strong>Training versus inference behaviour.</strong> Dropout and BatchNorm act differently. Keras passes <code>training=True/False</code> into <code>call</code>; PyTorch uses <code>model.train()</code> and <code>model.eval()</code>. Forgetting <code>eval()</code> before testing is one of the most common evaluation bugs.</li>\n<li><strong>Serialisation</strong>: <code>get_config</code> in Keras, <code>state_dict</code> in PyTorch (lesson 04.06).</li>\n</ul>\n<blockquote class=\"callout\"><p><strong class=\"callout-label\">Key idea</strong> A layer is parameters plus a forward function, created once and called many times. Keras infers input shapes lazily in <code>build</code>; PyTorch wants them in <code>__init__</code>. Both need an explicit training or inference mode.</p>\n</blockquote>\n<h3>A CNN with built-in layers</h3>\n<p>The tutorial rebuilds lesson 04.02&#39;s network with layers in a few lines:</p>\n<pre class=\"code\"><code class=\"language-python\">model = tf.keras.Sequential([\n    tf.keras.layers.Reshape((28, 28, 1)),\n    tf.keras.layers.Conv2D(16, 5, padding=&quot;same&quot;, activation=&quot;relu&quot;), tf.keras.layers.MaxPool2D(2),\n    tf.keras.layers.Conv2D(36, 5, padding=&quot;same&quot;, activation=&quot;relu&quot;), tf.keras.layers.MaxPool2D(2),\n    tf.keras.layers.Flatten(), tf.keras.layers.Dense(128, activation=&quot;relu&quot;), tf.keras.layers.Dense(10)])\n</code></pre>\n<p>Note TensorFlow&#39;s default image layout is channels-last <code>(N, H, W, C)</code>, while PyTorch uses <code>(N, C, H, W)</code>.</p>\n</section></details>"
